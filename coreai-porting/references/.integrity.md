# Reference-file integrity

Every reference file must begin with its own distinct `# ` heading. Two files sharing a heading
means one clobbered the other.

**How this file came to exist (2026-08-30).** A batch edit did:

```python
p = Path(K + "mlx-vs-coreai-fit.md"); s = p.read_text(); ...; p.write_text(s)
g = Path(K + "gradebook.md");         s = g.read_text(); ...; p.write_text(s)   # <-- p, not g
```

Reusing `p` wrote gradebook content into the fit journal. It survived two commits because the
follow-up edits used `str.replace`, which **silently no-ops when the anchor is missing** — so the
Wan section, the `state_names` axis and two gradebook rows were all written into a clobbered file
or dropped entirely, with no error at any point.

**Two rules that follow:**

1. In batch edits, never reuse a path variable. One path, one variable, written once.
2. `str.replace` returning the string unchanged is a FAILED edit. Assert the anchor exists before
   replacing, or the edit disappears silently.

Run `check.sh` after any batch edit to these references.
